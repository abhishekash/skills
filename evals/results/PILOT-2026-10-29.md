# Pilot evaluation — 2026-10-29

**Preliminary. Two paired runs per task. Not an effectiveness claim.**

## Setup

- Model/runner: the environment's default subagent model, identical for both arms
  (reported environment model: DeepSeek V4.1 Flash via `opencode-go`; the runner
  does not expose a separate model fingerprint).
- Tools/permissions: same read/write/edit/shell access; no package installs; no
  network dependencies.
- Budget: no explicit token/time cap; every run completed; none timed out.
- Fixtures/tasks: three per flagship, exactly as checked into `evals/`.
- Isolation: each arm ran in its own temporary directory prepared by
  `evals/harness.py`; the `without-skill` arm had no `skill/` directory.
- Starting point: every arm's scoped check failed before implementation, so the
  checks are sensitive to the required behavior.
- Repetitions: **two paired runs per task** (18 pairs, 36 arms total). Raw
  line-level scores are in [`PILOT-2026-10-29.json`](PILOT-2026-10-29.json).

## Secondary observations

- Round 1 patch size was mixed: with-skill was smaller in 3/9 tasks and larger in
  6/9.
- Round 2 patch size was mostly larger with the skill: with-skill was larger in
  **8/9** tasks (median +196 added lines), smaller in one (textual task 2).
- Across both rounds, with-skill was larger in 14/18 pairs.
- The extra size appears to be tests, docs, state models, and defensive handling,
  not unrelated rewrites.
- One round-1 with-skill run left an untracked `__pycache__/`; no without-skill run
  did.
- One round-1 with-skill run placed tests in `tests/` without `__init__.py`; a
  plain `discover -s .` found zero, while `discover -s tests` passed. That is an
  organization negative, not a functional failure.
- No functional regression occurred in either arm.

## Activation

Twelve of twelve activation decisions were correct:

| Flagship | Should activate | Should not activate |
|---|---|---|
| Textual | 2/2 | 2/2 |
| Ingestion | 2/2 | 2/2 |
| Status | 2/2 | 2/2 |

The decisions were semantic, not keyword matches (for example, "SQL migration"
and "React table" were correctly rejected).

## What this pilot does not establish

- Token and wall-clock cost: not captured by the subagent runner.
- Blind human rubric review: not performed.
- Generalization beyond these fixtures, this model, and this harness.
- Any improvement in functional correctness: no delta was observed.
- Any stable patch-size benefit: the direction is mixed and, in round 2, mostly
  larger with the skill.

## Interpretation

The tasks are solvable, the checks pass, and activation is correct. The skills did
**not** improve functional results in this pilot; they often increased patch
size. Keep the effectiveness claim open and run more repetitions with token/time
capture and blind review before claiming improvement.
